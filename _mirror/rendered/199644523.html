🔛是什么&为什么

是什么

烧录方式是将程序代码编译成固件，将固件写入 MCU（微控制器）的关键手段，用于实现嵌入式设备的功能开发、调试、维护及升级。通过不同的烧录方式，开发者可以根据需求完成代码的加载、验证和运行。

为什么​

不同烧录方式适用于不同的开发阶段和硬件设计需求。掌握并区分这些方式，可以帮助开发者应对多样化的芯片开发需求。学会区分不同的烧录方式，使开发者能够灵活应对不同芯片和应用场景的开发需求，如快速调试、批量生产烧录或远程升级。

🎦常见的三种烧写方式

ICP (In-Circuit Programming)
在线电路编程，是通过处理器的调试访问端口（Debug Access Port）烧录代码的一种方式。例如，在ARM Cortex架构中，常用的调试接口包括 SWD（Serial Wire Debug）和 JTAG（Joint Test Action Group）。开发者可以借助工具链如 ST-LINK、DAP-LINK 等实现程序的烧录。

ISP (In-System Programming)
在线系统编程，利用 MCU 厂商预置的 Bootloader，通过板载的 UART 或 USB 接口烧录代码。这种方式无需依赖外部调试器。以 ARM 单片机为例，其存储映射的代码区间通常预置了厂商提供的 Bootloader，从而支持通过 UART、USB 等多种方式实现程序下载（具体支持的接口方式依厂商的 Bootloader 实现而定）。

IAP (In-Application Programming)
在线应用编程，由开发者自行实现 Bootloader 功能。在 ARM 单片机中，Flash 的代码分区通常用于存储用户应用程序（上电后从此处执行用户代码）。开发者可以在 Flash 区间中存储自定义的 Bootloader 和应用程序。上电后，MCU 首先执行开发者实现的 Bootloader 代码，该 Bootloader 可提供程序下载、校验、升级以及启动等功能。这种方式常用于实现 OTA（Over-The-Air）远程升级功能，使得设备无需外部干预即可完成固件更新。


🎦通过串口实现OTA

🎞️RS485 实现 OTA 升级的场景

  • 支持多点通信（一主多从）。
  • 通信距离远，可达 1200 米（取决于速率和线缆质量）。
  • 抗干扰能力强（差分信号传输）。
  • 需要 RS485 转换芯片（如 MAX485）
  1. 工业设备网络升级
    RS485 支持多设备的总线连接，适合在工业自动化场景中通过主控设备集中管理和升级从设备的固件，例如 PLC 控制器、传感器、执行器等设备。
  2. 远程设备升级
    RS485 的长距离通信能力使其适合远程分布式设备的固件升级，例如农田灌溉控制器、路灯控制设备，以及分布式电力监控系统。
  3. 多设备轮询升级
    在需要升级多个设备的场景中，RS485 可通过地址轮询机制，实现主设备依次向从设备下发升级包，避免总线冲突。例如智能楼宇的电梯控制系统或安防门禁系统。
  4. 高干扰环境中的稳定升级
    RS485 的差分信号抗干扰能力强，适合在高电磁干扰的环境中进行固件升级，如工厂车间或铁路控制系统。

🎞️RS232 实现 OTA 升级的场景

  • 点对点通信。
  • 通信距离短（通常 ≤15 米）。
  • 抗干扰能力较弱（单端信号）。
  • 接口常见于老旧设备。
  • 需要 RS232 转换芯片（如 MAX232）
  1. 单设备现场维护
    RS232 常用于单设备的固件升级，适合在现场通过便携式工具连接设备进行维护和更新，如医疗设备、POS 机、仪器仪表等。
  2. 开发调试中的固件更新
    在开发阶段，RS232 可用于调试和升级嵌入式设备的固件，是一种方便的调试接口。
  3. 传统设备升级
    RS232 常出现在一些老旧系统中，这些设备的升级通常依赖其预留的串口，如 CNC 机床或早期的网络设备。
  4. 短距离设备固件更新
    RS232 的通信距离限制在短距离内，适合连接用户终端设备（如银行终端设备）进行固件升级。

🎞️TTL 实现 OTA 升级的场景

  • 点对点通信。
  • 通信距离非常短（通常 ≤1 米）。
  • 信号直接与 MCU 引脚匹配，无需额外硬件。
  • 常用于嵌入式开发中。
  • 直接连接 MCU 引脚
  1. 嵌入式设备固件下载
    TTL 接口广泛用于嵌入式设备中，适合开发过程中通过直接连接 MCU 的 TX/RX 引脚进行固件下载或更新。
  2. 模块化产品升级
    一些小型化或模块化产品（如 Wi-Fi 模块、蓝牙模块）通常预留 TTL 接口，方便通过串口工具或主机进行固件升级。
  3. 短距离维护与升级
    在便携式终端设备或需要直接访问 MCU 的场景中，TTL 是最简便的接口形式，无需额外硬件即可实现固件升级。
  4. 与 Bootloader 配合使用
    TTL 常用于开发者实现的 Bootloader 升级方案，支持通过 UART 下载和更新程序，适合轻量化的 OTA 升级场景。


🔚重点难点

  1. 掌握各烧写方式的适用场景及其技术特点：
  • ICP 的调试工具选择及接口协议（如 SWD 和 JTAG）。
  • ISP 的 Bootloader 配置及烧写工具链的使用。
  • IAP 的自定义 Bootloader 实现及 OTA 功能设计。
  1. 理解不同通信接口（如 RS485、RS232、TTL）的特点及其在 OTA 升级中的应用场景。

易错点

  1. ICP、ISP 和 IAP 的概念混淆，未能根据实际需求选择合适的烧写方式。
  2. 对 Bootloader 的地址分配和存储映射不清楚，导致烧写失败。
  3. RS485 和 RS232 通信特性区分不清（如抗干扰能力和通信距离），可能造成接口选型错误。
  4. TTL 接口连接时未正确匹配引脚，容易造成烧录失败或硬件损坏。
