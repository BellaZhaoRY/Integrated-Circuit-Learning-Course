注入灵魂：给机器“装系统”，比Windows还简单！

【引入：回想一下，你是怎么重装Windows系统的？】 大家都帮别人修过电脑、重装过系统吧？ 在Windows世界里，装系统是个“两步走”的体力活：

  1. 做启动盘： 找一个空U盘，下载个老毛桃或者Rufus工具，把Windows的ISO镜像刻录到U盘里，做成一个“PE启动盘”。
  2. 安装到硬盘： 把U盘插到电脑上，开机狂按 F12 或者 Delete 进 BIOS，设置U盘启动。进入一个简陋的界面后，再把系统一步步解压安装到电脑的 C盘（固态硬盘）里。安装完还得拔掉U盘重启。

是不是觉得步骤繁琐，甚至还有点容易选错盘把数据格式化了？

【反转：全志Linux的“一步到位”降维打击】 来到了我们的 HM-T113-CORE 面前，忘掉什么 BIOS、什么 PE 系统、什么 C盘 D盘！ 在咱们的嵌入式开发里，SD卡本身就是系统的“系统盘”。我们不需要U盘作为跳板，我们直接把系统“烙印”在真正的硬盘上！

全志的芯片，为我们提供了一个极其傻瓜化的官方工具，整个过程只需要点击几下鼠标。

【手把手实操：用 PhoenixCard 烧录系统】

第一步：准备你的“作案工具”

  • 一张普通的 Micro SD 卡（TF卡）。
  • 一个普通的 USB 读卡器。
  • 把卡插进读卡器，插到你的 Windows 电脑上。

第二步：打开全志烧卡神器 —— PhoenixCard（PhoenixCard4.2.8.rar）

  • 别去捣鼓那些复杂的命令行刻录工具，我们直接用全志官方提供的 PhoenixCard 4.2.8。这是一个免安装的小软件，双击打开。
  • 软件界面非常复古且直白，它会自动识别到你刚才插入的 SD 卡盘符。

第三步：选择镜像与烧写模式（敲黑板，避坑点！）

  • 选固件： 点击“固件”按钮，选中我们提前给大家编译好的 T113 Linux 系统镜像文件（.img 格式）。这就相当于你的 Windows 安装包。
  • 选模式（极其重要）： 看到界面中间那个“烧写模式”了吗？这里有“量产卡”和“启动卡”两个选项。
  • ❌ 千万别选“量产卡”！那是用来给板子上的 eMMC 批量刷机用的，选错的话，板子插上卡只会闪灯不会进系统。
  • ✅ 一定要勾选“启动卡”！ 我们的目的就是让这块板子直接从这张 SD 卡里启动 Linux 系统。


上图箭头指向的几个内容，千万不要选错了。

​

第四步：一键烧卡，见证奇迹

  • 点击那个大大的“烧卡”按钮。
  • 接下来你要做的，就是盯着屏幕上那条绿色的进度条跑完。由于我们的裁剪版 Linux 系统非常精简（只有20M），这个过程往往只需要十几秒。
  • 提示“烧写成功”后，拔下读卡器。

【点亮时刻：见证机器的第一次心跳】 现在，把你手里这张已经注入了 Linux 灵魂的 SD 卡，轻轻推入 HM-T113-CORE 板子背面的卡槽中。 接上串口线，插上电源！

​

如何进入linux系统：用 ADB “破门而入”

【实战避坑】 当你把烧录好系统的 SD 卡插进板子，通上电。很多网上老教程会告诉你：现在插上串口线，你就能看到绿色的代码滚动了！ 大错特错！默认linux系统是没有映射串口的。

因为我们烧录的是一个极其原始、纯净的系统镜像，默认状态下，它的“串口神经”根本就没有被激活配置。你插上串口线，只能面对一片黑屏。

【类比：Windows黑屏了怎么办？】 如果在 Windows 里，你的显卡驱动崩了，屏幕全黑，但主机还在运转，懂行的高手会怎么做？他们会用另一台电脑，通过网线用“远程桌面”连进去排查问题。 在我们的 T113 Linux 世界里，我们也有这样一个超级“后门”——ADB (Android Debug Bridge)。

这原本是安卓开发者的调试神器，但全志非常贴心地把它集成到了咱们的底层 Linux 里。通过板子上的 USB 调试 接口，我们能直接绕过串口和屏幕，瞬间穿透进系统内部！

【手把手实操：用 ADB 拿到系统最高权限】

第一步：一线连通（物理连接）

  • 找一根你平时给手机充电的 Type-C 数据线。
  • 一头插进 T113 核心板的 USB 调试接口，另一头直接插到你的 Windows 电脑上。
  • 给板子通电。这时候，你的 Windows 电脑会“叮咚”一声，就像插上了一个新 U 盘。

第二步：配置“黑客工具”（环境搭建）

  • 我们不需要安装几个 G 的庞大开发环境。在电脑上下载一个只有几兆大小的 ADB 工具包。
  • 把它解压到 C 盘根目录，然后配置一下 Windows 的“环境变量”（这里会配上超详细的图文步骤，小白也能一遍过）。
  • 将PhoeniSuit.zip解压到不包含中文空格的目录。
  • 配置步骤:
  1. 复制adb所在文件夹
  2. 配置到系统环境变量Path里
  3. 打开一个新的控制台
  4. 输入adb devices看到有哪些设备连进来了

​

第三步：敲下你的第一行指令（破门而入）

  • 在 Windows 电脑上按 Win + R，输入 cmd，召唤出黑色的命令提示符窗口。
  • 输入第一条测试指令：adb devices。
  • 如果下面跳出了一串英文字母和数字的组合，并且后面跟着 device 这个词。恭喜你，你的电脑已经成功和板子里的 Linux 灵魂接头了！

第四步：接管系统！

  • 激动人心的时刻到了，在黑框里敲下：adb shell 然后回车。
  • 瞬间，Windows 的盘符消失了，取而代之的是一行极具魔力的字符： root@t113:~#

【成就达成：你已经是造物主】 当你看到这个 # 号，意味着你已经拿到了这个 Linux 系统的最高管理员权限（Root）。 你已经成功站在了系统的内部！从现在开始，板子上的灯亮不亮、屏幕怎么显示、串口通不通，全凭你接下来在这个窗口里敲下的指令来决定。

新机落地大体检：用 Linux 命令看透硬件底牌

【引入：Windows 里的“设备管理器”，Linux 里怎么看？】 在 Windows 里，你想看 CPU 是几核、内存有多大、系统是什么版本，你会习惯性地去点“我的电脑 -> 属性”。 在嵌入式 Linux 的世界里，有一个终极奥义叫做：一切皆文件！ 你想看硬件信息？不需要复杂的图形界面，硬件状态全都被系统实时写在了特定的文本文件里。我们只需要用 cat（查看文件内容）或者系统自带的查询小工具，就能瞬间把板子的底牌看得清清楚楚。

现在，在你的 ADB 黑框框里，跟着我敲下这几条“体检指令”：

身份核验：这台电脑装的是什么系统？

1. 查户口本：系统发行版信息

  • 输入：cat /etc/os-release

你将看到：

  • Plaintext
[codeblock]
  • 降维解读： 这说明我们烧录的是基于开源神级路由系统 OpenWrt (版本 21.02) 深度定制的全志 Tina Linux 5.0。而且 t113-evb1 这个代号明确告诉你：系统已经成功认出了它脚下踩着的这块 HM-T113-CORE 硬件主板。

2. 查核心引擎：内核版本

  • 输入：uname -a
  • 你将看到：Linux TinaLinux 5.4.61 #1 SMP PREEMPT Wed Nov 19 09:06:18 CST 2025 armv7l GNU/Linux
  • 降维解读： 重点看 5.4.61。这是一个经典的 LTS（长期支持）内核版本，主打一个稳如老狗。后面跟着的编译时间（2025年11月19日）告诉你，这是一个非常新鲜热乎刚出炉的系统。armv7l 证实了这是一颗纯正的 32 位 ARM 架构处理器，且为小端模式。
  • (扩展小贴士：如果只想看纯净的版本号，敲 uname -r；只想看架构，敲 uname -m。)

盘点家当：我们的 CPU 和内存够用吗？

3. 拆解大脑：CPU 硬件信息

  • 输入：cat /proc/cpuinfo
  • 你将看到： 一大串英文，但你只需要敏锐地捕捉到两行字： processor : 0 ... model name : ARMv7 Processor rev 5 (v7l)processor : 1 ... model name : ARMv7 Processor rev 5 (v7l)
  • 降维解读： 0 是一颗心，1 是一颗心。实锤了！我们花几十块钱买的这颗全志 T113 芯片，是一颗货真价实的双核 Cortex-A7 处理器！

4. 查看仓库：内存真实容量

  • 输入：cat /proc/meminfo
  • 你将看到：MemTotal: 110088 kBMemFree: 67636 kB
  • 降维解读： 换算一下，总内存大约是 110MB。等等，T113 芯片手册上不是说内置了 128MB 内存吗？别慌，剩下的十几兆是被 Linux 内核这个“包租婆”自己预留吃掉了。 再看剩余内存，还有 67MB 空闲！在动辄需要 16GB 内存的 Windows 面前这少得可怜，但在嵌入式世界里，这 67MB 简直是一片广阔的天地，跑后续的电机控制、传感器读取甚至轻量级语音交互，绰绰有余！

动态监控：系统现在累不累？有没有网？

5. 唤醒任务管理器：系统负载监控

  • 输入：top （按 q 键可以退出）
  • 你将看到： 屏幕开始动态刷新。看第一行 95% idle，说明 CPU 闲得发慌，只有 5% 的负载。
  • 降维解读： 往下看进程列表，排在最前面吃资源的竟然是 adbd。这不奇怪，因为我们正通过 ADB 跟它聊天呢！你还会看到一个叫 wifi_daemon 的进程在后台躺着，这说明系统底层已经备好了 Wi-Fi 无线网络的支持，为我们后面接入云端打下了伏笔。

6. 检查网线插没插：网络接口状态

  • 输入：ip addr
  • 你将看到：1: lo: <LOOPBACK,UP,LOWER_UP> ... inet 127.0.0.1/8
  • 降维解读： 只有 lo（本地回环地址），没有看到代表有线网的 eth0 或者代表无线的 wlan0。这说明什么？说明我们的板子现在还是一个“信息孤岛”，虽然大脑跑起来了，但还没有连上互联网。不用急，这正是我们后续课程要去攻克的城池。
