软件层：开启 PPPoE 应用组件

现象： 系统提示 /bin/sh: pppd: not found。 原因： TinaLinux 默认为了精简体积，未编译 ppp 相关组件。 修复步骤： 在 SDK 根目录执行 make menuconfig，依次进入 Network -> ppp，选中以下两项（按 Y 设置为 [*]）：

  • ppp
  • ppp-mod-pppoe

(注：务必确保不要勾选 ppp-mod-pppoatm，以免引发后续依赖问题。)

内核层：开启底层 PPP 驱动

现象： 拨号日志报错 Please load the ppp_generic kernel module 且缺少 /dev/ppp。 原因： Linux 内核未开启 PPP 基础网络协议驱动。 修复步骤： 在 SDK 根目录执行 make kernel_menuconfig，进入 Device Drivers -> Network device support，勾选以下项为 <*>（静态编译进内核）：

  • <*> PPP (point-to-point protocol) support
  • <*> PPP filtering
  • <*> PPP support for async serial ports
  • <*> PPP Deflate compression
  • <*> PPP BSD-Compress compression
  • <*> PPP over Ethernet

完成后，执行 make clean && make -j4 && pack 进行全量编译，并重新烧录包含最新内核的完整固件。

环境层：解决网络鉴权断开问题

现象： 拨号日志显示鉴权成功并获取 IP，但瞬间报 LCP terminated by peer (User request)。 原因： 运营商或机房交换机的多设备在线限制、MAC 地址白名单限制，或 IPv6 协商异常。 排查与修复：

  1. 断开原来使用该账号拨号的旧设备，等待 2-3 分钟让服务器释放 Session。
  2. 若存在 MAC 地址绑定限制，在 network 配置文件中的 wan 接口下添加 option macaddr '旧设备MAC' 进行克隆。
