把 URDF 转成 MuJoCo XML 场景

2.1 为什么不能直接用 URDF

URDF 像一个"结构设计图"，它只描述机器人本身。

但 MuJoCo 的仿真需要一个"完整的场景"，除了机器人，还要有：

  • 地面
  • 灯光
  • 电机（执行器）
  • 根部自由度（让机器人整体能移动和旋转）
  • 仿真参数

所以我们的思路是：

  1. 先让 MuJoCo 自动读取 URDF，得到机器人结构
  2. 再人工补上场景元素

URDF 没有描述机器人整体怎么移动。MuJoCo 里需要显式加上：

[codeblock]
  • rootx：允许机器人整体前后滑动

2.3.4 执行器（电机）

有"关节"不代表有"电机"。URDF 不直接定义执行器，需要在 MJCF 中补充：

[codeblock]

这里用的是速度执行器：控制程序输出一个"目标速度"，执行器产生力来跟踪这个速度。kv="20" 是力增益，越大电机越"硬"。

实际力矩 = kv × (ctrl - 当前实际速度)

如果达不到目标速度，差距越大，执行器输出的力矩就越大，会一直"加力"去追。直到两种情况之一：

​

1. 追上目标速度 — 力矩自动减小到刚好维持的水平

2. 触达力矩上限 — 关节上 actuatorfrcrange="-100 100" 把力矩钳制在 ±100 以内，不会再往上加

所以达不到速度时，它不会报错也不会放弃，就是顶着最大力矩一直推。

3.1 控制器思路

完整行走控制器是 03_simple_walk.py

[codeblock]



​

它的核心思路非常简单：

  1. 一条腿支撑，一条腿摆动
  2. 支撑腿负责站稳，摆动腿抬起来向前迈
  3. 摆动腿碰到地面后，两条腿交换身份
  4. 循环往复，就走起来了

​

代码框架结构

每帧循环:

1. mj_step 推进物理

2. mj_forward 更新运动学

3. 接触检测 → 切换支撑腿

4. 获取足部位姿 + 躯干状态

5. 计算目标落脚点 (Capture Point)

6. 计算步高轨迹 (抛物线)

7. 支撑腿速度 (维持高度+倾角) → IK

8. 摆动腿速度 (追踪目标) → IK

9. 写入 ctrl (速度执行器)

3.4 怎么判断 "走得好不好"

三招判断法：

  1. X 轴位移持续增大：机器人一直在往前走
  2. Z 轴高度稳定在 1.0 左右：没有摔倒或飞起来
  3. 俯仰角没有剧烈翻转：身体没有前后倾倒超过 90 度

提示词在前进方向增加木块，验证模型的盲走能力。

总结

这节课的三步：

  1. 写 URDF：定义 5 个 link + 4 个 joint，画出一台简易双足机器人
  2. 转 MuJoCo XML：用 MjSpec 读入 URDF，补地面、根关节、执行器
  3. 写控制器：支撑/摆动交替，雅可比求关节速度，让机器人走起来

核心认知：URDF 描述机器人结构，MJCF 描述仿真场景，控制器描述怎么动。 三样东西凑齐，就能在 MuJoCo 里看到一台自己建模、自己控制的机器人往前走。
