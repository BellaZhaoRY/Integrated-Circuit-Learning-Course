计算 GPIO 编号

全志芯片的计算公式为：端口号 * 32 + 引脚索引

  • Port A = 0, B = 1, C = 2, D = 3, Port E = 4, F = 5
  • PE10 = 4 * 32 + 10 = 138
  • PF4 = 5*32 + 4 = 164
  • PD18 = 3*32 + 18 = 114

设备树 (Device Tree)

1. 核心定义
设备树（Device Tree）是一种描述硬件的数据结构。它通过一种树状结构（Tree Data Structure），向 Linux 内核传递板级硬件信息（如 CPU、内存、总线、外设控制器的物理地址、中断号、时钟、GPIO 复用等）。

2. 设计目的

  • 解耦合：将 硬件描述 与 内核源码 分离。
  • 通用性：允许同一个内核镜像（uImage/zImage）在不同的硬件平台（Board）上启动，只需加载对应的设备树文件（.dtb）。
  • 解决“代码膨胀”：取代了过去 ARM Linux 源码中大量硬编码的板级文件（如 arch/arm/mach-xxx/board-xxx.c），解决了 Linus Torvalds 诟病的 "ARM Churn" 问题。

​

我们先得看看在设备树（Device Tree）出现之前，嵌入式开发（包括现在的 STM32/GD32）是怎么干活的。

这种模式的特点是：

  • 硬编码 (Hardcoding)：硬件的信息（是 PA5 还是 PB8，基地址是多少）直接写死在 C 代码里。
  • 紧耦合：你的代码是专门为这一块板子编译的。这份编译好的二进制文件（.bin/.hex），绝对不可能跑在另一块引脚连接不同的板子上。

为什么单片机可以这么干？
因为单片机项目通常比较简单，软件和硬件是一一对应的。你修改了硬件，重新编译一下软件，理所当然，没人觉得有问题。

2. 以前的 Linux (2011年之前)：也是这么干的

在 2011 年之前，ARM 架构的 Linux 也是用类似 STM32 的方式在管理硬件。

那时候，Linux 内核源码里有一个庞大的目录叫 arch/arm/mach-xxx（machine 的缩写）。每当有厂家出一个新板子，工程师就要写一个 C 文件，比如 board-my-router.c，里面充斥着类似这样的代码：

这带来的灾难：
那时候正值 Android 和 ARM 爆发期，三星、高通、TI、全志发了无数款芯片，每款芯片又有无数家厂商做出了无数种开发板。

  • A 厂商把 LED 接在 GPIO 1。
  • B 厂商把 LED 接在 GPIO 2。
  • C 厂商换了个 WiFi 芯片。

于是，Linux 内核里塞满了成千上万个 board-xxx.c 文件。这些文件99% 的代码都是重复的，只有几行关于“引脚是几号”的区别。

Linux 内核变得极其臃肿，而且全是垃圾信息。

3. 爆发点：Linus Torvalds 发飙 (2011年)

Linux 之父 Linus Torvalds 是主要维护 x86 架构的，x86 也就是 PC 电脑，它们有 BIOS/UEFI 和 ACPI 标准，硬件会自己“自报家门”，所以 x86 的代码非常整洁。

当 Linus 看到 ARM 社区提交上来的代码合并请求（Pull Request）时，他崩溃了。因为 ARM 的更新包里，大部分不是系统核心功能的改进，而是成吨的、无聊的、重复的板级描述文件。

2011 年 3 月，Linus 在邮件列表中发出了那封著名的邮件，直接对 ARM 社区开骂（通俗翻译版）：

"Gaah. Guys, this whole ARM thing is a fucking pain in the ass."
（啊！伙计们，这整个 ARM 的东西简直就是搅屎棍/极其痛苦。）

他指责 ARM 社区没有秩序，代码里充满了“垃圾 (Junk)”和“混乱 (Churn)”。如果不解决这个问题，他就不再接收 ARM 的代码更新。

核心矛盾点：
Linus 认为：操作系统内核 (Kernel) 应该只关心“怎么开路”，而不应该关心“这条路在哪里”。
你不应该为了改一个 LED 的引脚，就要去重新编译整个操作系统内核！这太蠢了！

4. 解决方案：抄作业 (PowerPC 的设备树)

面对大佬的震怒，ARM 社区必须整改。他们发现 PowerPC 架构（IBM 的架构）早就解决这个问题了，用的就是 Open Firmware Device Tree。

于是，ARM 社区引入了设备树机制，把硬件描述从C 代码中踢了出去。

改革前 (STM32 风格)：

  • 源码：Linux内核 + 你的板子.c
  • 编译结果：一个只有你能用的内核镜像。
  • 修改硬件：修改 C 代码 -> 重编译内核。

改革后 (设备树风格)：

  • 源码：Linux内核 (通用) + 你的板子.dts (文本)
  • 编译结果：一个通用内核 uImage + 一个描述文件 dtb。
  • 修改硬件：修改 dts -> 编译 dtb -> 内核不用动！

第 1 节课：引脚的“数字门牌号”与控制面板

核心概念： 什么是 GPIO？它是芯片伸向物理世界的“神经触须”。

  • 实战动作 1（算门牌号）： 芯片不认识字母，只认识数字。教大家全志芯片的通用公式：端口号 $* 32 +$ 引脚索引 。
  • 例如：Port E=4，那么 PE10 引脚的编号就是 $4 * 32 + 10 = 138$。
  • 再比如：Port F=5，那么 PF4 引脚的编号就是 $5 * 32 + 4 = 164$。
  • 实战动作 2（开权限）： 烧录完系统去查看 /sys/class/gpio，发现报错 No such file or directory。这说明需要去内核配置里把开关打开 。教大家敲下 make kernel_menuconfig，在蓝底白字菜单中进入 Device Drivers -> GPIO Support，勾选 /sys/class/gpio/... (sysfs interface)。


第 2 节课：精心设计的“翻车”与 Linus 的震怒

  • 踩坑体验： 满怀期待地输入 echo 138 > /sys/class/gpio/export 尝试导出引脚，结果系统无情报错：sh: write error: Invalid argument。为什么算对了号码却报错？因为 PE10 在厂家默认的设备树文件里没有配置为 GPIO 功能 。
  • 降维历史课： 在 2011 年之前，ARM 架构的 Linux 像单片机一样，把硬件信息死死绑定在 C 代码里（硬编码、紧耦合） 。导致 Linux 内核塞满了成千上万垃圾的板级描述文件 。
  • 高潮： 2011年，Linux 之父 Linus Torvalds 彻底发飙，在邮件里大骂这简直是 "fucking pain in the ass"（极其痛苦） 。他强制要求：操作系统内核只管“怎么开路”，不能管“这条路在哪里” ！

第 3 节课：抄作业的艺术 —— 认识超级注册表

  • 破局： 面对大佬震怒，ARM 社区抄了 PowerPC 的作业，引入了设备树（Device Tree）。它是一种描述硬件的数据结构，成功把硬件描述与内核源码解耦合 。
  • 类比学习： 把设备树当成 Windows 的高级注册表。修改硬件引脚？以前要重编译整个内核，现在只需要修改 .dts 文本文件即可 。
  • 查看家底： 实操命令查看当前系统加载的设备树文件：cat /proc/device-tree/model。查看引脚被谁占用了：cat /sys/kernel/debug/pinctrl/pinctrl-handles。

从命令控制到 AI 脚本自动化

第 4 节课：上帝之手（手改第一份设备树）

  • 动作： 打开 Ubuntu 兵工厂里的 board.dts 文件 。
  • 干中学： 不教晦涩的设备树语法，直接告诉他们怎么“填表”。找到 GPIO 节点，模仿已有代码，强行把 PE10 注册为通用的输出引脚。
  • 打包闭环： 重新执行 pack 命令，生成新的 .img 并烧录。再次执行 export 138 命令，报错奇迹般消失了！

第 5 节课：掌控微观物理世界（Sysfs 接口实战）

  • 接线： 拿出一根杜邦线和一个 LED 灯模块，接在 HM-T113-CORE 的 PE10 引脚上。
  • 实战四步曲：
  1. 导出：echo 138 > /sys/class/gpio/export （向系统申请使用）。
  2. 方向：echo out > /sys/class/gpio/gpio138/direction （设为输出模式）。
  3. 干活：
  • 点亮：echo 1 > /sys/class/gpio/gpio138/value。
  • 熄灭：echo 0 > /sys/class/gpio/gpio138/value。
  1. 收工：echo 138 > /sys/class/gpio/unexport。
  • 成就感： 看着物理世界的小灯随着你在黑框框里敲下的回车键亮起、熄灭，建立起强烈的掌控感。

第 6 节课：绝不打算盘（AI 辅助编写 Shell 自动化脚本）

  • 痛点引入： 敲一次命令亮一下，敲一次熄灭一下，太累了。如果我们想让灯每秒闪烁一次，怎么办？因为大家没学过C语言，所以我们用 Shell 脚本！
  • AI 外挂启动： 直接演示如何给 AI（ChatGPT/豆包/Kimi）下达 Prompt指令：“我使用的是Linux系统，我想通过写入 /sys/class/gpio/gpio138/value 让一个LED灯闪烁。请帮我写一个Bash shell脚本，实现每隔1秒钟自动亮灭交替，循环10次。”
  • 实操验证： 拿到 AI 生成的代码，在板子上用 vi blink.sh 粘贴进去。赋予执行权限 chmod +x blink.sh，然后运行 ./blink.sh。
  • 升华： 看着板子上的灯自动按照规律闪烁, 要记得：现代开发不需要你死记硬背 while 循环和 sleep 怎么拼写，核心是知道背后的逻辑（向 sysfs 写入 0 和 1），然后让 AI 帮你完成语法的堆砌。
